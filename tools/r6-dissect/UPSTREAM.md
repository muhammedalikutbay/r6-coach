# Upstream and patches

- Upstream: https://github.com/redraskal/r6-dissect (MIT, see `LICENSE`)
- Vendored from `main` at commit `e6c2ca80f7f895e320ca0f8ded0f30136888ffac` (2025-09-15), without git history.
- Newer than the v0.24.0 release exe: upstream `main` already knows some Y10 map IDs (e.g. `ChaletY10`),
  so map names differ from the v0.24.0 build for some rounds. No Y11 map IDs are known; those print `Map(<id>)`
  and the Rust side resolves names.

## Patches (R6Koc)

Principle: unknown operator, map or role IDs must never panic; the raw ID stays in the output.

1. **Operator role fallback** (`dissect/operator_roles.go`, `dissect/genops.go`, `dissect/header.go`).
   `Operator.Role()` returned a `panic` for IDs missing from the role table. It now returns the new
   `Unknown` role (`TeamRole = "Unknown"`). Operator names already print as `Operator(<id>)` via the stringer.
   `operator_roles.go` is generated by `genops.go`: both were changed. The generator now emits
   `return Unknown` and no longer imports `fmt`; the generated file was edited by hand to the identical result
   (running the generator needs the stringer-built package, which was not re-run).
   Seen in the data: operator IDs 374667787937, 444310693746, 456757346397.
2. **Team role derivation** (`dissect/header.go`, `deriveTeamRoles`): players with an `Unknown` role are skipped,
   so the next player with a known operator decides the team roles.
3. **Round end with unknown players** (`dissect/time.go`, `dissect/utils.go`): kill/death/defuser feedback that
   names a player missing from the header used to index `Players[-1]` (index out of range panic).
   New helper `teamIndexByUsername` returns -1 and those entries are skipped.

4. **Operator swaps in Y11 replays** (`dissect/player.go` `readAtkOpSwap`, `dissect/reader.go` `pawnOwner`).
   Root cause: the header lists the operator picked at the start; operators changed during the prep phase arrive as
   `22 A9 26 0B E4` records (`MatchUpdateType` `OperatorSwap`). Upstream identified the swapping player by a "ui id"
   at a fixed +402 byte offset. In Y11 (code 9966156) that id no longer matches the header, so every swap was silently
   dropped and the pre-selected operator stayed (about 11-16% of rounds were wrong; e.g. Tracker `capitao`, replay `fuze`).
   Fix: the same marker also appears in 10 "header" records (one per player, holding the player's own id and, at
   +85, the id of the in-world pawn entity). We remember pawn id -> player id from those, then in a swap record find the
   first known pawn id and apply the operator to that player. Unknown records are logged at debug level and ignored.
   Validated against Tracker: operator match for H.A.N-01 went from 40/45 (88.9%) to 55/55 on the 10 overlapping matches
   (before: 5202ed0b not counted in the 45). Only offsets for the marker layout are hard-coded; a new game version can
   break them again, so re-check with the Tracker comparison after each Siege update.

5. **Weapon per kill** (`dissect/feedback.go`, `dissect/loadout.go`, `dissect/loadout_items.go`,
   `dissect/game_operators.go`, `dissect/player.go`, `dissect/reader.go`). Kill events gain three fields
   (all omitted when unknown):
   - `weaponId`: raw asset ID of the item that made the kill. The kill packet holds the field
     `22 F8 6C DD 65 08 <uint64 LE>` right after the headshot byte (found by lumina-r6; layout and validation
     from prestonwillis10/r6-dissect issue #28, MIT). `peekKillWeapon` looks for the tag in the 256 bytes
     after the headshot byte, reads only `r.b`, never moves the offset and never fails.
   - `weaponSlot`: `primary` | `secondary` | `gadget` | `ability`, the inventory slot that held that asset for
     the player the kill packet names (before any username correction). The inventory parser is adapted from
     prestonwillis10/r6-dissect `dissect/loadout.go` (MIT, commit `98e6a680bd322ba322689dde4b192b6946167705`);
     this fork has no round clock, so instead of the final prep-phase loadout every asset ever seen in a slot
     counts (inventories emptied at round end or re-sent after a swap do not erase anything).
   - `weaponItemId`: the game item ID of that slot in the killer operator's loadout block
     (`7A 8A C2 8F <operator game id>`, then `<item id u64> <slot crc32> <cat>` records; record layout from
     wnc-replay/replay-tool `analysis/events.go`, MIT). The asset ID is a different ID space from the name
     tables; the item ID is the key of `data/weapons.json`. Blocks are matched to players by operator name via
     `game_operators.go` (generated by `tools/gen-weapons` from wnc-replay/replay-tool `analysis/names.go`,
     commit `dd535f6499069c8268841fda76c68a04b19ba104`). Operators missing there (e.g. Noor, Solid Snake) get
     no item ID; an operator with two different items in the same slot gets none either.
   Measured on the 30 local Y11S3 matches (1192 kills): `weaponId` 100%, `weaponSlot` 98.9%, `weaponItemId`
   96.4%, name found 95.0%; every asset ID maps to one name (except the per-operator Nitro Cell variants).
   Output apart from these fields is identical to the build before this patch. Re-check after each Siege update.

6. **Round start time** (`dissect/header.go`). The header property `starttime` (Unix ms, the same moment as
   `datetime`, but real UTC) is parsed into `Header.StartTimeMs` and written as `startTime` in the JSON (omitted when
   the header has none or it does not parse). The v4 kill clips use it to place a round on the wall clock. Output
   apart from this field is unchanged.

Other callers of `Role()` (`player.go`, `site.go`) compare against `Defense`, so `Unknown` is safe there.

## Build and verify

- `tools/r6-dissect/build.ps1` builds `app/src-tauri/binaries/r6-dissect-x86_64-pc-windows-msvc.exe` (git-ignored).
- `tools/r6-dissect/verify.ps1 [-ReferenceExe <upstream exe>]` runs every `.rec` and every match folder
  and prints ok/fail counts; with a reference exe it also compares outputs.

## Left out of the vendored copy

`dissect/test/data/` (upstream replay fixtures, ~100 MB, contain other players' names) and `examples/` were
removed. Upstream Go tests in `dissect/test/` therefore cannot run here; use `verify.ps1` instead.
